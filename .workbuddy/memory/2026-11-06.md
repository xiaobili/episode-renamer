## OpenList 批量执行「并发 10 仍慢」的性能修复

**诊断（实测，非推测）**
- 用真实 `OpenListClient` 限流器 + 假 HTTP 压测：吞吐 ≈ 并发 / (请求间隔 + 单次往返)。
  并发 10 + 间隔 0.5s → 22.9 请求/秒；并发 2 + 0.5s → 4.0；并发 10 + 间隔 0.1 → 96。
  即「间隔」是主因，并发只决定并行度。
- 每文件请求数实测 5 次（同目录改名 + STRM 远端自定义目录），其中 2 次是**重复 mkdir**
  （`/strm`、`/strm/剧名` 每集重建），因为 `dir_cache` 是每文件新建的空 dict。
- 每个请求都 `async with httpx.AsyncClient(...)` → 每次请求新建 TCP/TLS 连接（60 请求 60 连接）。

**修复**
- `openlist_client._http_client()` + `aclose()`：复用一条连接池；`/login` 覆盖旧客户端前关闭、
  `/test` finally 关闭、`/logout` 逐个关闭。
- `execute_openlist_plans` 建**一份** `dir_cache` 传给 `execute_openlist_plan_once` →
  `execute_openlist_one(dir_cache=)` / `write_strm_for_plan(dir_cache=)`；`_ensure_dir` 与
  `ensure_remote_dir` 改为**先占位再 await**（并发下同一目录只建一次）。
- 只共享 mkdir 标记，**不共享目录内容列表**：内容在执行中会变，缓存会让「目标已存在」
  / 「旧 NFO 是否存在」读到过期快照（覆盖用户文件 / 漏搬 NFO）。
- 结果：每文件请求 5 → 3（15 → 11 次 / 3 文件）。

**判据**
- `test_directory_creation_is_shared_across_the_batch`（mkdir 恰好 2 次）
- `test_directory_cache_does_not_hide_a_name_conflict`（每文件仍各列一次目录）
- `test_http_client_is_reused_across_requests`（5 次请求只造 1 个客户端）
- 后端 399 passed；前端 12 个脚本全绿。README 增加「并发与吞吐」公式；设置页并发项补 hint。

## 镜像发布链路：GHCR 构建推送脚本 + Actions 工作流

**新增**
- `docker/build-and-push.sh`：构建并推送 `ghcr.io/xiaobili/episode-renamer`。
  镜像名从 `git remote origin` 推断（https / ssh 两种写法都认，路径强制小写）；
  版本优先级 `--tag` > HEAD 上的 git tag（去 `v` 前缀）> `frontend/package.json`。
  标签组合：`<版本>` + `latest`（可 `--no-latest`）+ `sha-<7位>`（`--sha`）。
  单架构走经典 `docker build` + 逐个 `docker push`（兼容旧构建器）；
  传 `-p/--platform` 才切 buildx，直接在 buildx 完成 `--push` 出多架构 manifest。
  登录目标跟着镜像名首段走（`ghcr.io` / `docker.io` / `localhost:5000`），
  凭据优先级 `$GHCR_TOKEN` → `$GITHUB_TOKEN` → `gh auth token` → 已有 `~/.docker/config.json` → 交互输入。
  `--dry-run` 只回显命令（且跳过守护进程校验），便于无 docker 环境预览。
- `.github/workflows/docker-publish.yml`：tag `v*.*.*` / main push / PR / 手动触发，
  单 job 内 buildx 出 amd64+arm64 `linux/amd64,linux/arm64`，用 `GITHUB_TOKEN` 推 GHCR，
  `docker/metadata-action` 生成 `1.2.3`/`1.2`/`latest`/`sha-xxxx` 四类标签，
  gha 缓存 + provenance + sbom，PR 只构建不推送。
- README 增「构建并推送到 GHCR」小节；`.dockerignore` 补 `.github/`。

**验证方式（本机无 docker 权限，走替身）**

  `imagetools inspect`，逐场景断言实际下发的命令行参数。
- 覆盖：默认推送、多架构 + sha、`--no-push`、`-i` 换 registry、登录失败中止、未知参数退出 1。
- 推断逻辑另在临时 git 仓库验证：ssh 远端、https 远端、HEAD 打 tag 后以 tag 为准、大小写转小写。
