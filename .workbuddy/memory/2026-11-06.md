# 2026-11-06

## OpenList 批量重命名整体后移（一次请求 + SSE 进度）

**目标**：OpenList 源的「并发控制 + 重命名」从前端移到后端，前端只发一次请求。

**后端**
- 新增 `backend/app/core/openlist_batch.py`：`PlanOutcome`、`execute_openlist_plan_once`
  （改名 → 每集 NFO → STRM）、`execute_openlist_plans`（文件级 Semaphore + 逐文件异常隔离 +
  进度回调）、`resolve_batch_concurrency`（批次内目标重名降级为串行）、`batch_result_payload`
  （与前端 `aggregateBatch` 同形）。
- 新增 `POST /api/rename/batch-execute`（`text/event-stream`）：start / progress / result / error
  四类帧；TMDB 在建流前解析（401 走普通 HTTP 错误）；批次内完成 finalize（剧集级 NFO）→
  folders（目录改名）；收尾失败以 `nfo_error` / `folders_error` 非致命返回。
- `OpenListClient` 增加只读属性 `max_concurrent`，文件级并发与 limiter 同源。
- 新增 `RenameBatchExecuteRequest`；路由仅接受 `source=openlist`（本地源仍走逐文件）。

**前端**
- `src/api/sse.js`（零 import 的 SSE 帧解析）+ `executeRenameBatch()`（fetch 流式，非 axios：
  axios 会缓冲整个流，进度条失去意义）。
- `workspace.executeAction`：`source === 'openlist'` 走单次批量请求，progress 帧驱动进度条，
  结果直接进对话框；`_remapScanPath(batch.folders_renamed)`；`nfo_error`/`folders_error` 弹降级提示。
- 本地源路径完全未动（仍逐文件并发 + finalize + folders）；`intervalMs` 因本地不再需要而移除。
- `renamePayload.js` 增加 `mode: 'batch'`（字段与 dry-run 相同）。

**判据**
- 后端：`tests/test_openlist_batch.py`（9）、`tests/test_rename_batch_route.py`（11）；全套 396 通过。
- 前端：新增 `scripts/check-rename-batch.mjs`（SSE 解析 + batch 载荷 18 项），已加入
  `check-all.mjs`；`check-execute-behaviour.mjs` 的 OpenList 场景 D/E/F/G 改写为 fetch + SSE
  替身，断言「只发一次请求 / 不再逐文件 / 不再单独 finalize·folders」；12 个脚本全绿。
