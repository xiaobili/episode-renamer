## 剧集文件夹改名 `剧名 (年份) [tmdbid-x]`（同日）

- 设计/规格：`docs/superpowers/specs/2026-10-27-show-folder-rename-design.md`。
- 用户选型：**带空格**（Emby 官方写法）+ 剧名取 **TMDB 本地化标题**；年份缺失时省略括号段。
- 新增 `models/show_folder.py`（`ShowFolderPlan`）与 `core/show_folder.py`：
  `build_show_folder_name` / `plan_show_folders` / `apply_local_show_folders` /
  `apply_openlist_show_folders`。剧集根复用 `nfo_writer.show_root_of`（新增的公开别名，
  内部仍是 `_show_root`）—— 季目录上溯只允许有一份实现。
- **顺序是设计核心**：execute → finalize → **folders**。先改目录会让
  `write_nfo_files` 的 `mkdir(parents=True)` 在旧名下重建目录，产出「只有 tvshow.nfo
  的空文件夹」。前端 `executeAction` 里三个块的位置就是这个顺序，已被
  `check-execute-behaviour.mjs` 场景 F 用调用下标钉住（变异测试：交换两块 → 恰好 1 红）。
- 新接口 `POST /api/rename/folders`（`RenameFoldersRequest`）：不读 `conflict_strategy`
  （目录不覆盖、不自动编号），OpenList 侧先列父目录判撞名再 `rename`（远端没有 exists）。
- 拒绝矩阵：未匹配 TMDB / 同目录混放 / 目录嵌在别的剧里（只拒祖先）/ 已是目标名（幂等）/
  **剧集目录直接挂在根下**（`/media` 这种挂载点，新增 `ROOT_TOO_SHALLOW_REASON`）。
- 前端：左栏「同时重命名剧集文件夹」勾选框（默认关）；FileTable 的 `NFO / STRM` 列
  改名为 `NFO / STRM / 目录` 并显示目标目录末段；ResultDialog 新增「剧集文件夹」块
  （单位是**部剧**不是文件）。执行后 `_remapScanPath` 把 `path` 前缀改写到新目录，
  否则「扫的就是剧目录」那种最常见的用法会导致重扫必失败。

## Docker 改为单镜像自包含（同日）

- 目标：一个镜像含全部依赖，运行期不需要宿主 Node/Python，可 `docker save` 离线分发。
- `Dockerfile` 重写为三阶段：`frontend`（node:20-bookworm-slim，`npm ci` + `vite build`）
  → `python-deps`（python:3.12-slim-bookworm，`python -m venv /opt/venv` 后装
  requirements，build-essential 只留在这一层）→ `runtime`（只搬 `/opt/venv` + 源码
  + dist，无编译器）。runtime 为**最后一个 stage**，即默认构建目标。
- 关键取舍：
  - `python-deps` 里**不能**设 `PIP_NO_CACHE_DIR`，否则 `--mount=type=cache` 白挂；
    runtime 里才设。
  - 去掉 `# syntax=docker/dockerfile:1`（省掉拉 frontend 镜像的额外网络依赖），
    但保留 `RUN --mount=type=cache`，因此必须 BuildKit（Docker 24+）。
  - 非 root：`APP_UID`/`APP_GID` 构建参数建 `app` 用户，写 NFO/STRM 不在宿主机留 root 文件。
  - `config.py` 导入时 `mkdir(data/, logs/)`，故 runtime 预建 `/app/data`、`/app/logs` 并 chown；
    `BASE_DIR` 与 `main.py` 的 `frontend/dist` 都落在 `/app`，与 COPY 落点一致。
  - `docker/entrypoint.sh`：HOST/PORT 取环境变量，worker 固定 1（内存文件缓存），
    有参数则 `exec "$@"` 覆盖；ENV 里加 `HOME=/app`（useradd --no-create-home）。
- `.dockerignore` 收窄上下文：测试、data/logs、frontend/dist、docs/screenshot、`.env*` 全排除。
- `docker-compose.yml` 改为 `image: episode-renamer:latest` + `MEDIA_DIR`/`APP_PORT` 变量替换。
- **本环境无法验证 `docker build`**：`/var/run/docker.sock` 属 `root:docker`，当前 uid 1000
  不在 docker 组（无 CAP_DAC_OVERRIDE），python 运行时也已损坏。已做的验证：
  `docker compose config` 通过、`sh -n` 入口脚本通过、桩程序验证 HOST/PORT/传参三种分支、
  COPY 源文件存在性核对。
- **首次真实构建报错**：用户环境的 `docker compose up -d --build` 走的是**经典构建器**
  （输出 `Step 4/36` + 「Removed intermediate container」），`RUN --mount=type=cache` 直接
  报 "the --mount option requires BuildKit"。处置：删掉两处 cache mount 改普通 `RUN`，
  并在 `python-deps` 补回 `PIP_NO_CACHE_DIR=1`（无挂载时 pip 缓存会进镜像层）。
  教训：**这个项目不能假设 BuildKit**，Dockerfile 保持零 BuildKit 专属语法。
