# 2026-10-24

## BrowseDialog 加搜索框（当前目录过滤）

**需求**：目录过多时查找不便，在选择目录对话框底部（列表与按钮栏之间）加搜索框。

**改动**
- 新增 `frontend/src/components/browseFilter.js`（零依赖纯函数）：`normalizeQuery`（trim + NFKC + toLowerCase）、`filterDirs`。NFKC 是为了全角输入法打出的字母/数字能命中半角目录名。
- `BrowseDialog.vue`：搜索框放在列表下方、按钮栏上方（不被 `max-h-[280px]` 滚动区吃掉，位置恒定）；`filteredDirs` 是**列表渲染 / 键盘下标 / 下钻取路径**的唯一来源（原来 `onListKeydown` 取 `dirs.value[current]`，换成过滤后数组必须同步改，否则下标错位）；`load()` 成功后清空 `query`（覆盖下钻、双击、面包屑、上级四条路径）；无匹配文案与「此目录无子目录」分开；`role="listbox"/"option"` + `aria-live` 播报结果数。

**踩到的坑（重要）**
- `AppModal` 的 keydown 挂在 `document` 的 **capture** 阶段。搜索框里 `stopPropagation()` + `preventDefault()` 对 Esc 完全无效 —— 捕获阶段早于目标元素的冒泡监听器（实测顺序恒为 doc-capture → target → 冒泡）。修复：`AppModal` 拆成 capture/bubble 两个监听器共用同一 `onKeydown`，用 `capturePass` 标志位分派；捕获拍遇到「焦点在面板内」让位，冒泡拍在 `defaultPrevented` 时不再关窗。
- 变异测试发现过一条「永远为真」的断言：用全文件 `includes` 查 `removeEventListener` 时，`onClose` 与 `onBeforeUnmount` 各有一份，删掉一处仍能命中。改为按函数体（`fnBody`）分别校验，5 个变异全部能被抓到。
- **教训**：不要用 `copyFileSync(备份, 工作区文件)` 做变异测试的复原。该 shim 会走「安全删除」通道，替换失败时目标文件已被删除（`AppModal.vue` 曾被整个删掉，靠 `git checkout` 恢复）。变异测试要在仓库**外**的临时目录做。

**判据**：`cd frontend && node scripts/check-all.mjs` → 11 个脚本全通过（新增 `check-browse-filter.mjs`、`check-appmodal-escape.mjs`，已同步加入 `check-all.mjs` 硬编码名单）。
